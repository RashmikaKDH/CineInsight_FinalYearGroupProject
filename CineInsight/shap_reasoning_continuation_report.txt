4. PACING, RETRY AND QUOTA-PAUSE SPECIFICATIONS
--------------------------------------------------------------------------------
- Configured Rate Limits (Gemini 3.5 Flash Lite):
  * 15 Requests Per Minute (RPM)
  * 250,000 Input Tokens Per Minute (TPM)
  * 500 Requests Per Day (RPD)

- Request Pacing:
  * Strict minimum 15.0 seconds between the start of ANY two requests (both initial
    and retry attempts). At 15s delay, the process operates at a maximum of 4 RPM,
    well below the 15 RPM project quota limit.
  * Batch size capped at 5 segments per request and payload capped at 12,000 characters.
    Even with dense tokens, input TPM remains well under 10% of the 250,000 TPM limit.

- Finite Bounded Retries:
  * Maximum 3 attempts per batch (1 initial + 2 retries).
  * 429 Temporary Throttling: Waits `max(15.0, server_retry_delay) + jitter` (0.5-2.0s).
    Every attempt passes through the 15s pacing barrier.
  * 5xx Server Errors & Connection Drops: Exponential backoff `min(60.0, 15.0 * 2^attempt) + jitter`.
  * Daily Quota Exhaustion / Zero Quota: Detected via response error markers (e.g.
    `requests per day`, `daily`, `rpd`, `limit: 0`, `free_tier_requests_per_day` or
    `retry-after > 60s`). Does NOT enter an infinite retry loop or sleep for hours.
    Pauses immediately, preserves partial results to CSV, marks batch and remaining
    pending segments as `waiting_budget`, and returns an honest partial result.
  * Invalid Credentials / 404 / 400: Fatal; stops immediately without retry.
  * No local assumption is made regarding exclusive access to the project quota,
    and no false remaining-quota counters are displayed.


5. CACHE COMPATIBILITY & RESUME BEHAVIOR
--------------------------------------------------------------------------------
- Atomic Persistence:
  * Validated explanation batches are saved immediately to `gemini_explanations.json`
    via `.tmp.json` atomic file replacement (`os.replace`).
  * The dataframe report is saved atomically to the final CSV (`save_csv`) after
    every batch or status transition.
- Resumption Logic:
  * When resuming, previously completed explanations (`reasoning_status == 'completed'`)
    and explanations cached in `gemini_explanations.json` are loaded immediately
    without making API calls.
  * Any segments previously marked `waiting_budget`, `waiting_after_error`, or `error`
    are reset to `pending` and processed.
  * Media preparation, feature vectors, model predictions, and SHAP calculations
    are never rerun during recovery.
